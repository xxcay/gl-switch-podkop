# gl-switch-podkop

Превращает физический рычажок на роутере GL.iNet в аппаратный **переключатель полного VPN** для [podkop](https://github.com/itdoginfo/podkop).

Щёлкнули в одну сторону → IP вашего устройства добавляется в «Полностью маршрутизированные IP-адреса» podkop, и весь его трафик идёт через VPN/туннель.
Щёлкнули обратно → IP убирается, устройство возвращается к обычной (частичной) маршрутизации podkop по спискам.

Без перезагрузки роутера и без кликов в LuCI — просто рычажок.

**Проверено на:** GL.iNet Beryl AX (GL-MT3000), заводская прошивка GL.iNet на базе OpenWrt 24.10.

**Может подойти для:** других роутеров GL.iNet с рычажком, которые поддерживают функцию **Toggle Button Settings** в веб-панели (например Slate AX / GL-AXT1800, Slate 7 / GL-BE3600, Beryl 7 / GL-MT3600BE), — **при условии, что на них устанавливается сам podkop** (нужна OpenWrt 24.10+ и ~20 МБ свободного места). Подробности — в разделе [Для каких роутеров это может подойти](#для-каких-роутеров-это-может-подойти).

Не подходит для «чистой» прошивки с openwrt.org — там нет механизма GL.iNet, на который опирается скрипт (см. [Как это работает](#как-это-работает)).

## Зачем это нужно

У многих роутеров GL.iNet (например Beryl AX / GL-MT3000) сбоку есть рычажок. В штатной прошивке на него можно повесить только несколько фиксированных функций (Wi‑Fi, VPN-клиент GL.iNet, Tor, AdGuard Home, LED и т.п.), и ни одна из них не умеет работать с podkop.

Трафик через [podkop](https://github.com/itdoginfo/podkop) обычно маршрутизируется точечно — по доменам и подсетям. Когда нужно прогнать через VPN вообще весь трафик конкретного устройства, приходится заходить в LuCI и вручную добавлять его IP в «Полностью маршрутизированные IP-адреса», а потом так же вручную убирать. Этот проект делает то же самое щелчком рычажка.

## Установка

**Требования:**
- роутер GL.iNet с рычажком и заводской прошивкой GL.iNet (на роутере должна существовать папка `/etc/gl-switch.d/`);
- [podkop](https://github.com/itdoginfo/podkop) уже установлен и работает (настроена хотя бы одна секция);
- доступ к роутеру по SSH под `root`.

Подключитесь к роутеру по SSH и выполните:

```sh
wget -O /tmp/install.sh https://raw.githubusercontent.com/xxcay/gl-switch-podkop/main/install.sh
sh /tmp/install.sh
```

Скрипт спросит IP-адрес устройства, трафик которого нужно полностью заворачивать в VPN (например вашего компьютера). Укажите IP **устройства**, а не роутера (не `192.168.8.1`). Несколько устройств можно указать через пробел.

После этого скрипт:

1. создаст `/etc/gl-switch.d/podkop.sh` — обработчик рычажка;
2. переключит рычажок на этот обработчик: `uci set switch-button.@main[0].func='podkop'`.

Узнать IP устройства можно в LuCI: *Статус → Обзор* (список активных DHCP-аренд). Лучше закрепить за устройством постоянный адрес (*Сеть → DHCP и DNS → Статические аренды*), иначе после смены IP рычажок перестанет на него действовать.

## Использование

Щёлкните рычажком и проверьте в логе:

```sh
logread -f
```

Должна появиться строка вида (выход из просмотра — `Ctrl+C`):

```
... user.notice gl-switch-podkop: podkop fully_routed_ips: add [192.168.8.50] (arg=on)
```

Перед ней в логе будет много строк `podkop: [info] ...` — это нормально, podkop пересобирает свои правила (reload). Роутер при этом не перезагружается, другие настройки не трогаются.

Проверить, что IP действительно добавлен:

```sh
uci show podkop | grep fully_routed_ips
```

- рычажок в положении ON → выводится строка с вашим IP;
- рычажок в положении OFF → команда ничего не выводит (это значит, что IP в списке нет).

### Если ON и OFF перепутаны

По документации GL.iNet положение **ON — рычажок влево**, OFF — вправо. Если вам удобнее наоборот, откройте `/etc/gl-switch.d/podkop.sh` и в строке с `MODE=` замените `"on"` на `"off"`:

```sh
# было
[ "$1" = "on" ] && MODE="add" || MODE="del"
# стало
[ "$1" = "off" ] && MODE="add" || MODE="del"
```

Учтите, что при повторном запуске `install.sh` эта правка перезапишется.

## Удаление

```sh
wget -O /tmp/uninstall.sh https://raw.githubusercontent.com/xxcay/gl-switch-podkop/main/uninstall.sh
sh /tmp/uninstall.sh
```

Скрипт вернёт рычажок в режим `none` («Без функции») и удалит `/etc/gl-switch.d/podkop.sh`. IP, который на этот момент находится в «Полностью маршрутизированных IP-адресах», **не удаляется** — если нужно, уберите его вручную в LuCI на странице Podkop, вкладка «Секции».

## Как это работает

В заводской прошивке GL.iNet рычажком управляет служба `gl-switch` (пакет `gl-sdk4-switch-button`). При каждом щелчке она запускает скрипт `/etc/gl-switch.d/<функция>.sh` с аргументом `on` или `off`. Имя функции берётся из настройки `switch-button.@main[0].func`. Именно её меняет пункт **Toggle Button Settings** в веб-панели GL.iNet: например, при выборе VPN вызывается готовый `vpn.sh`. Для значения `none` («Без функции») скрипта нет, и рычажок ничего не делает.

Это **не** стандартный механизм OpenWrt `/etc/rc.button/`. На Beryl AX обычный `rc.button`-скрипт для рычажка не срабатывал: событие перехватывает `gl-switch`.

`install.sh` добавляет свою функцию `podkop` и переключает на неё рычажок. Сгенерированный скрипт `/etc/gl-switch.d/podkop.sh`:

- берёт список IP, указанный при установке;
- при `on` добавляет каждый IP в список `fully_routed_ips` **всех** секций podkop (типа `section` в `/etc/config/podkop`), поэтому работает и с одной секцией `Main`, и с несколькими;
- при `off` убирает эти IP;
- сохраняет конфиг (`uci commit podkop`) и выполняет `/etc/init.d/podkop reload`, чтобы podkop пересобрал правила маршрутизации;
- пишет строку в системный лог с тегом `gl-switch-podkop`.

Состояние хранится в конфиге podkop, поэтому переживает перезагрузку роутера. Если переключить рычажок, пока роутер выключен, то подхватит ли `gl-switch` новое положение при загрузке, не проверялось. В таком случае просто щёлкните рычажком туда и обратно.

## Известные ограничения

- **Кратковременный разрыв.** Во время `podkop reload` (обычно 5–10 секунд) podkop пересоздаёт свои правила, и трафик, идущий через него, может ненадолго прерваться у всех устройств, не только у вашего.
- **У рычажка одна функция.** Если потом выбрать для рычажка другую функцию в веб-панели GL.iNet (Toggle Button Settings), настройка `func` перезапишется, и этот скрипт перестанет вызываться. Чтобы вернуть его, снова запустите `install.sh`.
- **Список IP задаётся при установке.** Чтобы изменить его, запустите `install.sh` заново: он перезапишет `/etc/gl-switch.d/podkop.sh`.
- **Несколько секций podkop.** IP добавляется сразу во все секции. Проверено только с одной секцией. Если нужен выбор конкретной секции, заведите issue.
- **Обновление прошивки.** Файлы лежат в `/etc`, поэтому при обновлении прошивки с сохранением настроек должны сохраниться. После сброса к заводским настройкам установку нужно повторить.

## Для каких роутеров это может подойти

Нужны одновременно два условия:

1. **Рычажок с поддержкой Toggle Button Settings.** По [официальной документации GL.iNet](https://docs.gl-inet.com/router/en/4/interface_guide/toggle_button_settings/) эту функцию поддерживают:
   - GL-BE10000 (Slate 7 Pro)
   - GL-MG1300 (Mango 2)
   - GL-MT3600BE (Beryl 7)
   - GL-BE3600 (Slate 7)
   - GL-MT3000 (Beryl AX) — **проверено**
   - GL-AXT1800 (Slate AX)
   - GL-MT1300 (Beryl)
   - GL-SFT1200 (Opal)
   - GL-A1300 (Slate Plus)
   - GL-MT300N-V2 (Mango)
   - GL-AR300M Series (Shadow)
   - GL-E750V2 (Mudi V2)
   - GL-AR750S (Slate)
   - GL-AR750 (Creta)

2. **На роутер ставится podkop.** По [требованиям podkop](https://podkop.net/docs/install/) нужна OpenWrt **24.10 или новее** и **минимум 20 МБ** свободного места. У многих старых моделей из списка выше (например Mango, Shadow, Creta, Slate / AR750S, Mudi V2) заводская прошивка основана на более старой OpenWrt и/или флеш-память слишком маленькая, поэтому podkop, а значит и этот скрипт, там, скорее всего, не заработает. Проверить версию OpenWrt на роутере можно так:

   ```sh
   grep DISTRIB_RELEASE /etc/openwrt_release
   ```

По той же документации **рычажка нет** (Toggle Button не поддерживается) у GL-BE14000 (Flint 4), GL-E5800 (Mudi 7), GL-MT5000 (Brume 3), GL-BE6500 (Flint 3e), GL-BE9300 (Flint 3), GL-X2000 (Spitz Plus), GL-B3000 (Marble), GL-MT6000 (Flint 2), GL-X3000 (Spitz AX), GL-XE3000 (Puli AX), GL-AX1800 (Flint), GL-MT2500/GL-MT2500A (Brume 2), GL-X750/GL-X750V2 (Spitz), GL-XE300 (Puli), GL-B1300 (Convexa-B), GL-AP1300 (Cirrus) и GL-X300B (Collie). На них скрипт работать не будет.

Реально проверено только на GL-MT3000 (Beryl AX). Если попробуете на другой модели, напишите в issue, сработало или нет, и список обновится.
