# gl-switch-podkop

Превращает физический рычажок на роутере GL.iNet в аппаратный **переключатель полного VPN** для [podkop](https://github.com/itdoginfo/podkop).

Щёлкнули в одну сторону → весь трафик вашего устройства добавляется в «Полностью маршрутизированные IP-адреса» podkop и идёт через VPN/туннель.
Щёлкнули обратно → устройство возвращается к обычной (частичной) маршрутизации podkop по правилам.

Без перезагрузки, без кликов в LuCI — просто рычажок.

**Проверено на:** GL.iNet Beryl AX (GL-MT3000), заводская прошивка GL.iNet на базе OpenWrt 24.10.
**Должно также работать на:** любом роутере GL.iNet с физическим переключателем режима/VPN на "SDK4"-прошивке (там, где в веб-панели есть **System → Toggle Button Settings**) — например Slate AX (GL-AXT1800), Beryl (GL-MT1300), Opal (GL-SFT1200), Slate 7 (GL-BE3600) и других моделях с пакетом `gl-sdk4-switch-button` и хуками `/etc/gl-switch.d/*.sh` (полный список — в разделе [Для каких роутеров это может подойти](#для-каких-роутеров-это-может-подойти)). Не подходит для ванильной прошивки с openwrt.org — см. [Как это работает](#как-это-работает). Если попробуете на другой модели — заведите issue в любом случае, сработало или нет, чтобы дополнить список.

## Проблема

У роутеров GL.iNet (например Beryl AX / GL-MT3000) есть физический рычажок сбоку. В штатной прошивке его функции урезаны, а трафик через [podkop](https://github.com/itdoginfo/podkop) обычно маршрутизируется точечно — по доменам/подсетям. Когда нужно прогнать через VPN вообще весь трафик с конкретного устройства, приходится лезть в LuCI и вручную добавлять его IP в «Полностью маршрутизированные IP-адреса». Этот проект вешает эту операцию на физический рычажок: щёлкнул — весь трафик в VPN, щёлкнул обратно — вернулся обычный режим.

## Установка

Подключитесь к роутеру по SSH под root, затем:

```sh
wget -O /tmp/install.sh https://raw.githubusercontent.com/xxcay/gl-switch-podkop/main/install.sh
sh /tmp/install.sh
```

Либо вручную: скопируйте `install.sh` на роутер и запустите `sh install.sh`. Скрипт спросит IP-адрес(а), которые нужно полностью маршрутизировать, а затем:

1. создаст `/etc/gl-switch.d/podkop.sh` (сам обработчик переключателя),
2. подключит к нему рычажок: `uci set switch-button.@main[0].func='podkop'`.

**Требования:** [podkop](https://github.com/itdoginfo/podkop) должен быть уже установлен и настроен (хотя бы одна секция).

## Использование

Щёлкните рычажком. Проверьте, что сработало:

```sh
logread -f
```
должна появиться строка вида:
```
gl-switch-podkop: podkop fully_routed_ips: add 192.168.1.50 (arg=on)
```

и убедитесь, что конфиг реально изменился:
```sh
uci show podkop | grep fully_routed_ips
```

Если ON/OFF оказались перепутаны относительно физического направления рычажка — откройте `/etc/gl-switch.d/podkop.sh` и поменяйте местами ветки `on`/`off` в этой строке:

```sh
[ "$1" = "on" ] && MODE="add" || MODE="del"
```

## Удаление

```sh
sh uninstall.sh
```

Это вернёт переключатель в режим `none` и удалит скрипт-обработчик. IP, который уже был добавлен в `fully_routed_ips` у podkop, **не удаляется** автоматически — уберите его вручную в LuCI (*Podkop → Секции*), если нужно.

## Как это работает

В прошивке GL.iNet есть небольшой демон (пакет `gl-sdk4-switch-button`), который следит за GPIO переключателя и при каждом щелчке запускает `/etc/gl-switch.d/<режим>.sh on` или `... off`, где `<режим>` берётся из `uci get switch-button.@main[0].func` (штатные варианты GL.iNet: `wifi`, `vpn`, `tor`, `led`, `repeater`, `adguardhome`, `wireguard`, `openvpn`, `none` — под каждый уже есть готовый скрипт в `/etc/gl-switch.d/`). Это **не** стандартный механизм OpenWrt `/etc/rc.button/` — на этой прошивке переключатель полностью принадлежит `gl-switch`, поэтому обычный `rc.button`-скрипт никогда не сработает.

`install.sh` добавляет ещё один режим (`podkop`) и переключает рычажок на него. Сгенерированный скрипт:

- берёт список локальных IP, заданный при установке,
- при `arg=on` добавляет каждый IP в список `fully_routed_ips` **всех** секций типа `section` в `/etc/config/podkop` (сработает и если у вас одна секция `Main`, и если их несколько),
- при `arg=off` — убирает их,
- коммитит и запускает `/etc/init.d/podkop reload` (пересобирает конфиг sing-box/nftables на лету — несколько секунд, без перезагрузки, не трогает ничего вне podkop).

Физически это именно переключатель (`EV_SW`/`BTN_0` в device tree), а не кнопка, поэтому при загрузке роутера драйвер сам сообщает текущее положение переключателя — то есть нужный режим маршрутизации применяется автоматически сразу после старта роутера, без необходимости щёлкать рычажком заново.

## Известные ограничения

- Список IP фиксируется при установке. Чтобы его изменить, запустите `install.sh` заново (он перезапишет `/etc/gl-switch.d/podkop.sh`).
- Проверено только с одной секцией podkop. Если секций несколько, IP полностью маршрутизируется во *всех* сразу — заводите issue/PR, если нужен контроль по отдельным секциям.
- Штатные режимы GL.iNet (`vpn`, `wifi` и т.д.) никак не связаны с podkop и этим скриптом не затрагиваются — их можно использовать на других роутерах/сценариях, просто не одновременно с `podkop` на этом же рычажке.

## Для каких роутеров это может подойти

Согласно официальной документации GL.iNet ([Toggle Button Settings](https://docs.gl-inet.com/router/en/4/interface_guide/toggle_button_settings/)), физический рычажок/кнопка и один и тот же механизм `gl-switch` есть на следующих моделях:

- GL-BE10000 (Slate 7 Pro)
- GL-MG1300 (Mango 2)
- GL-MT3600BE (Beryl 7)
- GL-BE3600 (Slate 7)
- GL-MT3000 (Beryl AX) — **на этой модели протестировано**
- GL-AXT1800 (Slate AX)
- GL-MT1300 (Beryl)
- GL-SFT1200 (Opal)
- GL-A1300 (Slate Plus)
- GL-MT300N-V2 (Mango)
- GL-AR300M (Shadow)
- GL-E750V2 (Mudi V2)
- GL-AR750S (Slate)
- GL-AR750 (Creta)

На остальных моделях GL.iNet (например Flint 2 / GL-MT6000, Marble / GL-B3000, Flint / GL-AX1800 и т.д.) физического переключателя либо нет, либо он не подключён к этому механизму — там скрипт не сработает.

Реально проверялось только на GL-MT3000 (Beryl AX). Если попробуете на другой модели из списка — напишите в issue, сработало или нет, чтобы дополнить README.
